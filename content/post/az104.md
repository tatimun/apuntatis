### Modulo 1: *Implementación de aplicaciones web de Azure App Service*
# Azure App Service

Azure App Service es una plataforma administrada para simplificar la implementacion y el escalado de aplicaciones web, backend, movile y API. 
Permite lenguajes como .NET, Java, Node.js, Python o PHP y despliega en entornos Windows o Linux, tambien si tenes un contenedor podes usarlo para desplegar en un tu contenedor customizado

Permite escalar hacia arriba o abajo:
- Verticalmente: Agrega numero de nucleo o cantidad de memoria RAM
- Horizontalmente: Capacidad para aumentar o disminuir numero de instancias de la maquina que ejecuta la app web

### ¿Deployment Slot? ¿Que es?
Es una ranura con otra copia de tu app corriendo al mismo tiempo pero sin afectar tu productivo.
Es como tener un ambiente desarollo o homologacion y podes desplegarla en el mismo servicio sin tener que levantar otro servicio aparte 

Podes subir una nueva version y probarla sin romper nada! Y encima te genera una URL para probarlo aparte de tu produccion

OJO! No se intermcabia toda la config:
- Secrets
- Connection Strings
- App Settings

No se comparten para no apuntar a misma DB por ejemplo


### App service en Linux
Podes utilizar contenedores o una base de Linux, admite muchas imagenes integradas espeficiadas. Los lenguajes adminitos: Net, Java, NodeJS Python y PHP 

Para verificar

    az webapp list-runtimes --os-type linux

WARNING ⚠
No podes usar el plan mas barato
Algunas opciones del portan pueden no aparecer
El disco no es tan rapido si usas runtimes integrados (Node, Java, Python etc) ya que el codigo no vive en el contenedor, vive en un volumen en un Azure Storage llevando a que sea mas lento y variable


### App Service Enviroment -Planes de Azure App Service
Es App Servivce pero en una burbuja privada solo para vos, es una caracteristica que aisla el entorno para ejecutar aplicaciones de App Service, ofrece mayor seguridad

Este entorno puede correr en una propia Vnet, no comparte infra con nadie.
Tambien aumenta el costo del mismo 

Sigue siendo una App Service pero con mayores caracteristicas 

---
Las aplicaciones se ejecutan siempre en un plan de App Service, esto define un conjunto de recursos de proceso para ejecutar las apps. 

Se crean por  regiones y se crea un cnjunto de recursos de proceso para ese plan en esa region.

Contiene: 
- Sistema Operativo
- Region
- Numero de instnacias de maquinas virtuales
- Tamaño de instnacias
- Plan de tarifa: Determina caracteristicas de app service y cuanto para por el plan.


Proceso Compartido: Gratis y Compartido, ejecuta una aplicacion en una misma maquina virtual junto a otras app service de otros clientes, asignan cuotas de CPU a cada app, no se puede escalar horizontalmente


Computo dedicado: Basico, Estandar, Premiums V1,V2,V3 ejecuta apps en maquinas virtuales dedicadas.
Aislado: ejecutan ne maquinas dedicadas en redes virtuales de Azure dedicadas

3. Actualizar el slot de despliegue cambiando la etiqueta de la imagen, el app service se reinicia y descarga la nueva imagen

### Autenticacion y autorizacion

App Service proporciona compatibilidad integrada en la aplicacion web o la API sin tener que implementarlas uno mismo, no requiere lenguaje SDK o conocimiento de seguridad, se puede integrar con EntraID, Google, Facebook, etc.

App Service usa identidad federada de terceros para almacenar usuarios

#### Como funciona?

El componente de mdw de auth y autorizacion se ejecuta en la misma maquina virtual de la app, cada solicitud http entrante pasa por ella antes de la app. 
1. Autentica usuarios y clientes con identidiaddes espeficiados del proveedor
2. Valida almacena y actualiza tokens de OAuth emitidos por provedores
3. Administra la sesion autenticada
4. Inserta informacion de identidad en encabezados de solicitud HTTP

### Caracteristicas de Red de App Service

Se puede acceder a ap'licaciones hospedadas en app service directamente a traves de iunternet, y estas solo pueden acceder a puntos de conexion hospedados en internet. 

DOS TIPOS DE IMPLEMENTACIONES PRINCIPALES EN AZURE APP SERVICE:

El servicio publico multitenant hospeda planes de servicio de aplicaciones de distintos niveles: Free, Compartido Basico, Estandar, Premiu, v1 v2 v3
La instancia de ASE de un solo inquilino hospeda planes de App Service de SKU aislada directamente de la red virtual 


Hay dos tipos de roles:

Front-end: reciben tráfico HTTP/HTTPS.
Workers: ejecutan tu aplicación.

Todo vive en una red compartida, por eso:
❌ No se puede conectar directamente a tu red (VNet como si fuera una VM). 

PEROOOOOOOOOOOOOOO, Azure te da caracteristicas

Controla quien puede entrar con una direccion IP asignada a la App (no compartida), restricciones de acceso por rangos de IP, servicew endpoints y private endpoints para entrar desde VNET


📦 Planes de App Service y multiinquilencia

Free / Shared → workers multiinquilino.
Basic / Standard / Premium → workers dedicados al plan.

Las IPs de salida:
Dependen del tipo de máquina virtual del plan.
Cambian si cambiás de familia (Basic → PremiumV3).


Azure App Service is multi-tenant and cannot be directly connected to a VNet; instead, it uses inbound and outbound networking features


Direcciones IP de salida adicionales .

        az webapp show \
            --resource-group <group_name> \
            --name <app_name> \
            --query outboundIpAddresses \
            --output tsv

Para encontrar todas las posibles direcciones IP salientes de la aplicación, independientemente de los planes de tarifa, ejecute el siguiente comando en Cloud Shell.

        az webapp show \
            --resource-group <group_name> \
            --name <app_name> \
            --query possibleOutboundIpAddresses \
            --output tsv
